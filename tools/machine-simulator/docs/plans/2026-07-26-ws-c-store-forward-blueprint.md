# WS-C — Durable Store-and-Forward — Blueprint (code-grounded)

> Wire the SDK's disk WAL on, add a pump (SDK replay is NOT automatic), a size guardrail, and fix an ack-label bug. 5 TDD tasks, subagent-driven.

## Decisive facts (verified)
- **SDK is a SHARED example file — DO NOT edit it.** `St4i.EdgeCore.csproj:9` links `..\..\..\..\examples\device-client\csharp\St4iDeviceClient.cs`. Any missing WAL behavior is built in `St4i.EdgeCore`, never by patching the SDK.
- **SDK WAL API**: ctor `queuePath` is a single **JSONL FILE path** (not a dir); null=RAM. Line = `{kind,path,payload,queuedAt}` (payload already has idempotencyKey baked in). Retryable HTTP {429,500,502,503,504} + network exceptions; exp backoff 0.5s→30s, maxRetries 4. Enqueue only after retries exhausted (permanent 4xx never queued). **Replay = `FlushQueueAsync` (public), triggered ONLY opportunistically at the top of each Submit*Async when QueueLen>0, or explicitly. NO background thread.** DrainQueue reads FIFO top-to-bottom, truncates file, re-enqueues failures at end. Replay resends ONLY `payload` (kind/queuedAt/historical NOT sent). No size/TTL/eviction. `FlushQueueAsync` returns `(int sent,int kept)` only (no per-row correlation).
- **Idempotency**: `Normalizer.BuildIdempotencyKey` (Mapping/Normalizer.cs:20-38) bakes a DETERMINISTIC key into every ProcessResult/Inspection payload → replay dedup is solid. **Telemetry `Sample` has NO key field → at-least-once dup risk on replay (flag, cannot fix by wiring).**
- **Construction sites** (verified): (1) `src/St4i.EngineApi/Program.cs:59-64` (`queuePath:null` L63); (2) `src/St4i.EdgeCore/Transport/TransportCoordinator.cs:88` (null in `RebuildLive`); (3) `src/St4iMachineSimulator/App.xaml.cs:119-124` (WPF app DI — a real 4th site the "3 sites" framing missed). **NOT** `EdgeWorker.cs:70` (hardcodes `DemoTransport` — stale in master plan; defer to WS-F1). `App.xaml.cs:565-570` (`--live-smoke`) → leave null deliberately.
- **FleetHost shares ONE EdgePipeline/`_transport`/`mk_`/`machineCode`** for the whole fleet (FleetHost.cs:385,777; machineCode default "ENGINE-API-01"). → WAL is one file per PROCESS/gateway-machineCode, named `Sanitize(machineCode)+".jsonl"` (reuse `CredentialStore.SanitizeFileName`, promote to internal static).
- **ACK-LABEL BUG**: `MachineState.cs:332` + `MachineViewModel.cs:361`: `!ack.Success ? "ERR" : ack.Duplicate ? "dup" : ack.Queued ? "queued" : "ok"` — a real disk-buffered write is `Success:false,Queued:true` → mislabeled "ERR". Fix: check Queued first, distinguish client-buffered (`Success:false,Queued:true`) vs server-buffered (`Success:true,Queued:true`) vs error. `LiveTransport.cs:78-84` already returns `(Success:false,Queued:true)` on `St4iNetworkException`.
- **"Ships-dark" flags** `PROCESS_/OT_/INSPECTION_STORE_FORWARD_ENABLED` are SERVER-side ingest-resilience (buffer when platform DB down) in repo-root `.env.example` — ORTHOGONAL to the client WAL. Do NOT conflate/gate on them.
- **Auto-mode caveat**: `AutoTransport` routes 4/5 calls to DemoTransport once fallen back → those never reach the WAL. **Durability holds only in `TransportMode.Live`** (the shipped default). Document, don't change. The "Mất mạng demo" preset swaps a DemoTransport → not usable to test WS-C; use direct LiveTransport + fake-handler tests.

Env overrides `ST4I_WAL_DIR/ENABLED/MAX_BYTES` (mirror Program.cs:123-125 `ST4I_HISTORIAN_DIR`). `ResolveQueueFile(opts, machineCode)` = `Path.Combine(dir, Sanitize(machineCode)+".jsonl")` (pure fn of machineCode → RebuildLive preserves backlog on settings edits that keep machineCode). ## Replay/UX design
- Order preserved (single uncontested flush); idempotent for ProcessResult/Inspection; NO per-row historical flag possible via SDK → recommend **Option A** (aggregate "N drained" signal + corrected Queued ack label), NOT Option B (parallel EdgeCore WAL) which is out of scope.
- **Pump required**: `WalFlushPump` (model on HistorianWriter: IAsyncDisposable, own CTS, Task.Run loop, delegate log hooks, ~15s tick) closing over `coordinator.Live` freshly each tick (survives RebuildLive), skip while Mode==Demo; `event Action<int>? BacklogDrained`. Add `LiveTransport.FlushBacklogAsync(ct) => _client.FlushQueueAsync(ct)` passthrough.
- **Size guardrail**: `WalMaintenance` drop-oldest trim to MaxBytes (atomic temp+File.Move like MachineConfigStore.WriteAllTextAtomic), return dropped count (log; mirror server policy "counted+warned"), invoked from pump tick.
