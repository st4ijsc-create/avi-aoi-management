3. **Lifecycle** = `Provisioned → Commissioning → Active → Maintenance → Decommissioned`. A machine is upserted as **Active** on register (it's operational). Manual transitions via `PUT /v1/assets/{code}/lifecycle` (Engineer, audited).
4. **Drift** — the asset record stores a `ConfigChecksum` (computed at upsert); live drift state is surfaced by joining the asset with the machine's existing `MachineState.DriftState` (config-sync already computes it). No new drift engine.
5. **Modbus roster** — `StartLocked` excludes `DriverKind.Modbus` from the simulated `effectiveFleet` (so a Modbus machine isn't double-driven); the Modbus machine is seeded into the roster via `RegisterMachine` at startup (from `ModbusRegisterMap.MachineCode`), giving it a `MachineState` → it appears in `Snapshot` + historian.
